InputIt only ever sees pixels

One frame can't tell you which way the bird is moving, so the network reads four at once. It commits to flap / don't every 4th frame and holds it (frame_skip=4).

ObjectiveThree numbers, and a guess about the future

From that, the network learns Q(s,a): how much total future reward it expects if it takes action a right now. Acting is just picking the bigger of the two numbers. Training is Double DQN — one network chooses, a slower copy scores — which curbs, though doesn't eliminate, the optimism that makes a plain DQN over-value everything.

Architecture1,258,659 parameters

No BatchNorm, no dropout. With a target network, anything that makes the forward pass depend on the rest of the batch leaves the update rule with no fixed point to converge to.

Why two headsMost frames don't need a decision

Subtracting mean(A) isn't polish. Without it, V and A aren't pinned down by Q at all — add a constant to one, subtract it from the other, and Q is unchanged — so the two heads quietly drift apart during training.

The browser portChecked, not assumed

1,200 observation frames, pixel-identical 300 decisions, same action as PyTorch 6×10−3 max Q deviation (fp16)

This page runs a hand-written JavaScript forward pass — no ONNX runtime, no WASM blob — so the entire download is the weights themselves (fp16, 2.52 MB). The parity harness ships in web/tools/ and needs no Python to re-run.

Both AI numbers are the same weights down two different code paths. Flappy Bird scores are close to geometric — the spread is as wide as the average — so treat any single mean as ±20% unless it comes with a sample size. The human figure is a small sample: a sense of scale, not a baseline.

This same architecture, on an earlier version of the training pipeline, plateaued at 1.3 pipes after 100,000 episodes. The fix wasn't a better algorithm or more compute — it was about a dozen structural bugs in the data path: a terminal-state flag silently dropped 75% of the time, a target network left in training mode, a reward scale that saturated the loss. The write-ups for the failures are in the repo alongside the fixes.

# 11 · 泛化：让网络学会玩游戏，而不是背下一个窄分布

这一篇讲一个本项目真实遇到、并且用实验量化了的问题：
**智能体在训练环境里拿 218 分，换个稍微不同的地图只剩 2 分。**

代码：[`game/flappy_env.py: _sample_pipe()`](../../game/flappy_env.py)

---

## 1. 症状

第一版训练出来的模型很强 —— 100 局纯贪婪评测平均 389.6 根管道，
中位数 521，46% 的局跑满长度上限还活着。

然后把**同一个模型**放进一个管道布局随机化的环境里：

| 环境 | 平均过管道 | 中位数 | 跑满上限仍活着 |
|---|---|---|---|
| 训练分布（固定布局） | **275.7** | 416 | 53 / 100 |
| 随机化布局（未见过） | **2.4** | 2.0 | 0 / 100 |

**崩塌 115 倍。** 随机基线是 0.63 根 —— 也就是说，换个地图之后，
这个"专家"只比乱按好 4 倍。

（100 局纯贪婪，单局上限 3000 次决策。完整的两模型 × 五环境矩阵见第 8 节。）

---

## 2. 病因：训练分布太窄

把原来的环境量出来（`game/flappy_env.py` 改造前）：

```
缝隙中心 y : 8 个离散取值，160..230，跨度 70px
             留 38px 余量后理论可用范围是 224px  ->  只覆盖 31%
缝隙大小   : 完全固定 = 100
水平间距   : 完全固定 = 144
```

来源是这两行：

```python
GAP_Y_CHOICES = (30, 40, 50, 60, 70, 80, 90, 100)
gap_y = random.choice(GAP_Y_CHOICES) + int(BASEY * 0.2)
```

**注意这不是"背下了一张固定地图"** —— 管道高度每局确实在随机变。
准确的说法是**对一个很窄的分布过拟合**：智能体只需要应付
一个 70px 的竖直窗口、一个固定的 100px 缝隙、一个固定的 144px 水平节奏。

在这种条件下，一套"锁定固定竖直节奏"的窄策略就足够拿高分了。
它从来没有被迫学会"看清楚下一个缝隙在哪、有多大、多远，然后规划"。

> ### 一个常见的误解
>
> "那我把随机种子换成系统当前时间，环境不就每时每刻都不一样了吗？"
>
> **不会。** 环境每根管道本来就在调 `random.choice()`，每一局的序列
> 已经是不同的。种子只决定**抽到哪一条序列**，不改变**从多窄的分布里抽**。
>
> 换成时间种子唯一的效果是让训练不可复现 —— 你再也没法做
> "改了 A 之后是变好还是变坏"的对照实验，而这在 RL 里是最重要的能力。
>
> **要解决的是分布的宽度，不是随机数的来源。**

## 3. 药方：域随机化

Domain randomization：**训练时就让环境参数在一个宽范围内随机变化**，
逼迫策略对这些参数保持鲁棒，而不是钻某一组参数的空子。

本项目随机化三个维度，而且是**逐根管道**独立采样 ——
所以同一局之内地图就在不断变化，不只是局与局之间不同：

```python
CONFIG:
    randomize_pipes=True,
    pipe_gap_range=(80.0, 165.0),       # 缝隙大小
    pipe_spacing_range=(115.0, 200.0),  # 水平间距（原来恒为 144）
    pipe_edge_margin=38.0,              # 缝隙上下沿距天花板/地面的最小余量
    pipe_max_delta_frac=0.6,            # 见下面的可达性约束
```

改造前后实测对比：

| 维度 | 固定 | 随机化 |
|---|---|---|
| 缝隙中心跨度 | 70 px（8 个取值） | **239 px（876 个取值）** |
| 覆盖可用竖直空间 | 17% | **59%** |
| 缝隙大小 | 固定 100 | **80 – 165** |
| 水平间距 | 固定 144 | **115 – 200（631 个取值）** |

---

## 4. 关键细节：可达性约束

这是整段代码唯一有技术含量的地方，**不加会毁掉训练**。

如果三个维度完全独立地随机采样，相邻两个缝隙的中心可能相差 239px，
而它们的水平间距可能只有 115px —— 小鸟**物理上根本飞不过去**。

### 推导

```
管道左移速度         : 5 px/帧
间距 S px            -> 小鸟有 S/5 帧的时间完成竖直转移
小鸟极限上升速度     : 5 px/帧（持续扇翅时 velY 恒为 -5）
小鸟极限下降速度     : 5 px/帧（终端速度 playerMaxVelY = +5）
=> 这段时间内最多移动 ±(5 × S/5) = ±S px
```

这是**零余量**的理论极限（要求全程满速、到达时速度不受控）。
留出余量后：

```python
|Δcenter| <= max_delta_frac × S        # 默认 0.6
```

### 为什么这件事重要

生成一根过不去的管道，**不是"更难"，是"不可学"**。
网络会收到一批无论采取什么动作都会死的样本，这些样本会：

- 污染价值估计（把某些明明安全的状态标记为低价值）
- 稀释真正有信息量的梯度
- 让评测指标失去意义（分数里混进了运气成分）

**难度和噪声是两回事。** 域随机化要增加的是难度和多样性，不是不可控的噪声。

单测 10 (`test_pipe_randomization`) 同时验证两件事：
分布确实变宽了，**且**落差/间距的比值从不超过 0.6。

```
[10] OK  center span 70->235px (224 values), gap 0->84px,
         spacing 0->84px, reach ratio max 0.597 <= 0.600
```

## 5. 实现要点

### 缝隙大小要逐根记录

缝隙大小不再是全局常量，所以势能函数不能再读 `self.pipe_gap`：

```python
# 错：所有管道用同一个 gap
gap_center = nxt['y'] + PIPE_HEIGHT + self.pipe_gap / 2.0

# 对：读这根管道自己的 gap
gap_center = nxt['y'] + PIPE_HEIGHT + nxt['gap'] / 2.0
```

上管道的 dict 里因此多存了一个 `'gap'` 键。

### 生成管道的触发条件要改

原来的触发条件把间距锁死了：

```python
if 0 < self.upperPipes[0]['x'] < 5:      # 第一根快出左边界了
    ...spawn at x = SCREENWIDTH + 10
```

这样间距恒等于屏幕宽度的一半，**根本没法随机**。改成按"最后一根距屏幕
右缘已经够 `_next_spacing`"来判断：

```python
if self.upperPipes[-1]['x'] <= SCREENWIDTH - self._next_spacing:
    newPipe = self._sample_pipe(self.upperPipes[-1]['x'] + self._next_spacing)
    self._next_spacing = self._sample_spacing()
```

### 可达性链条要从小鸟的出生高度起算

第一根缝隙也必须够得着：

```python
# reset()
self._last_gap_center = float(self.playery + PLAYER_HEIGHT / 2.0)
```

否则开局就可能直接送一根飞不到的管道。

## 6. 旧存档怎么办

域随机化是后加的。**老存档必须继续在老环境里评测**，否则会莫名其妙地低分：

```python
# flappy/config.py: config_from_checkpoint()
if 'randomize_pipes' not in saved:
    cfg['randomize_pipes'] = False
```

**缺项一律按"当时的行为"补，不按"今天的默认"补。**
这是所有带配置演进的项目都会踩的坑：新加一个默认开启的选项，
所有历史结果就都失去了可比性，而且失效得悄无声息。

## 7. 人类基线

随机化之后环境明显更难了，"难到什么程度"最好有个人类参照。
用 `python play.py --human` 实测 20 局：

| | 平均 | 中位数 | 最高 |
|---|---|---|---|
| 随机策略（p_flap=0.2） | 0.63 | — | — |
| 旧模型（只在固定分布上训练） | 2.4 | 2.0 | 11 |
| **人类**（20 局） | **6.8** | 5.0 | 31 |
| 新模型（随机分布上训练到 ε=0.01） | **56.8** | 39.0 | 286 |

两点值得注意：

1. **旧模型（2.4）打不过人（6.8）**，尽管它在自己的训练分布上能过 275 根。
   这比任何曲线都更能说明"它不是比人强，只是很擅长那一个窄分布"。
2. **新模型是人类的 8.4 倍**，训练总共约 70 分钟。

> 公平起见：人类基线是在 cv2 窗口里用"点空格"操作、30 FPS 下打出来的。
> cv2 只能拿到按键事件、拿不到按下/抬起状态，手感不如原生游戏。
> 所以这个 6.8 是"这套操作方式下的人类成绩"，不是人类上限。

顺带一个物理小知识，你自己玩的时候会亲身体会到：一次扇翅令 `velY = -5`，
重力 `+0.5/帧`，约 19 帧后净位移归零 —— 所以**稳定悬停的节奏是每 5 帧点一下**。
这正是 `sample_random_action()` 里 `p_flap = 0.2`（= 1/5）的由来，
见 [07 · 探索策略](07-exploration.md)。

## 8. 完整泛化矩阵

两个模型 × 五个环境，每格 **100 局纯贪婪（ε=0）**，单局上限 3000 次决策。
两个模型都训练到 ε=0.01 的利用期。

| 评测环境 | 旧模型<br>固定 gap 100 上训练 | 新模型<br>随机 gap 80–165 上训练 |
|---|---|---|
| 固定 gap 100 　←　*旧模型的训练分布* | **275.7**　（中位 416，53% 跑满上限） | 239.6　（中位 221，29% 跑满上限） |
| 固定 gap 85 | 4.4 | **34.8**　（7.9×） |
| 固定 gap 75 | 1.2 | **5.2**　（4.3×） |
| 随机 gap 80–165 　←　*新模型的训练分布* | 2.4 | **56.8**　（23.5×） |
| 随机 gap 60–80 　（两者都没见过） | 0.5 | **2.6**　（5.3×） |

复现命令：

```bash
python eval.py <ckpt> --episodes 100 --max-decisions 3000                  # 训练分布
python eval.py <ckpt> --episodes 100 --no-randomize --pipe-gap 85          # 固定窄缝
python eval.py <ckpt> --episodes 100 --gap-range 60 80                     # 更窄的随机缝隙
```

`eval.py` 会在输出里标注 `[training distribution]` 还是
`[SHIFTED - generalisation test]` —— 泛化测试最容易犯的错就是忘了自己在哪个分布上评的。

### 怎么读这张表

**① 旧模型极其脆弱。** 275.7 → 4.4，只因为缝隙从 100px 变成 85px。
**改一个参数 15 个像素，"专家"就废了 —— 崩塌 63 倍。**
这比第 1 节那个 104 倍更能说明问题，因为 85px 甚至不是什么奇怪的设置，
它只是"稍微窄一点"。

**② 新模型在每一个它没见过的分布上都赢，而且差距巨大**（4.3× 到 23.5×）。

**③ 唯一输的一格是旧模型的老家**，而且只低 13%（239.6 vs 275.7）——
新模型从没在固定 gap 100 上训练过。注意这一格两个模型都被上限截断了很多局
（53% 和 29%），所以两个数字都是**下界**，差距实际比看上去还小。

**④ 但新模型也没有超越自己的训练支撑集。** gap 60–80 全部低于训练下界 80，
成绩掉到 2.6。这不是"钻空子"，是域随机化**已知的边界**：
它买到的是随机化范围**之内**的鲁棒性（插值），不是范围**之外**的外推。

**⑤ gap 75 本身就接近不可能。** 小鸟高 24px，75px 的缝隙只剩 51px 余量，
还要配上随机的中心跳变。旧模型在那里只有 1.2 —— 所以新模型的 5.2
不该简单读成"失败"，那个难度对谁都很残酷。

### 结论

**域随机化真的让网络学到了更通用的技能，而不是换了个分布继续背。**
最强的证据是第三行和第一行的对比：新模型在**从没训练过**的固定 gap 100 上
拿到 239.6，接近专门在那里训练的旧模型（275.7）；
而旧模型在新模型的分布上只有 2.4。

**迁移是单向的** —— 宽分布训练出来的策略能覆盖窄分布，反之不行。
这正是域随机化的核心承诺。

## 9. 方法论：怎么设计这类实验

上面那张表能说明问题，靠的是三条纪律：

1. **必须有对照模型。** 只看"新模型在 gap 75 上只有 5.2"什么也说明不了 ——
   直到你知道旧模型在那里只有 1.2，才明白 5.2 是好是坏。
2. **必须区分插值和外推。** gap 85 在新模型的训练范围内（80–165），
   gap 75 在范围外。前者测的是鲁棒性，后者测的是外推 ——
   **两者失败的含义完全不同**，混在一起谈会得出错误结论。
3. **必须报告截断比例。** 固定 gap 100 那一格有 53% 和 29% 的局跑满了上限，
   意味着两个均值都是下界。不说这个，就等于在用一把有上限的尺子量身高
   却不提尺子只有 3 米。

## 10. 还能怎么随机化

本项目目前只随机化管道布局。更彻底的做法还包括：

| 维度 | 怎么做 | 代价 |
|---|---|---|
| **物理参数** | 重力、扇翅力度逐局采样 | 网络必须从帧栈**推断**动力学，难度大幅上升 |
| **视觉** | 背景、管道颜色、亮度扰动 | 逼迫网络关注几何而非颜色 |
| **观测噪声** | 随机丢帧、加噪声 | 提升对不完美感知的鲁棒性 |
| **管道速度** | 逐局采样水平速度 | 打破"固定节奏"的最后一点残余 |

其中**物理参数随机化**最有意思：它让任务从"MDP"变成了
"POMDP + 隐藏参数"，智能体必须先用几帧观测**推断**当前这局的重力有多大，
再据此行动。这是元学习（meta-RL）的入门形态。

但要注意：**每加一个随机维度，样本复杂度都会上升。**
先把管道布局这一层做对、确认能收敛，再考虑加下一层。

## 小结

| 点 | 结论 |
|---|---|
| 症状 | 旧模型：训练分布 275.7 根 → 随机分布 2.4 根，崩塌 115 倍 |
| 更尖锐的症状 | 旧模型：缝隙只窄 15px（100→85），275.7 → 4.4，崩塌 63 倍 |
| 疗效 | 新模型在没训练过的固定 gap 100 上拿 239.6，接近专训的 275.7；反向只有 2.4 |
| 边界 | 迁移是单向的，且不越出随机化范围：gap 60–80 仍然只有 2.6 |
| 病因 | 分布太窄（缝隙中心只覆盖 17% 的可用空间，大小和间距全固定） |
| **不是**病因 | 随机种子。换时间种子只会让训练不可复现，多样性一点不增加 |
| 药方 | 域随机化，三个维度逐根独立采样 |
| 必须配套 | 可达性约束，否则生成的是不可学的必死样本 |
| 兼容性 | 老存档缺字段时按"当时的行为"补，不按今天的默认补 |
| 怎么验证 | 在没见过的难度上评测，和训练分布上的成绩对比 |

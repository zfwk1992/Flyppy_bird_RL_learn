# 10 · 怎么诊断训练

RL 里最缺的技能不是调参，是**判断训练是不是健康的**。

监督学习里 loss 和准确率就够了。RL 里这两个都会骗你 ——
**loss 下降可能恰恰是坏消息**。这一篇讲该看什么、什么样子算正常。

工具：[`monitor.py`](../../monitor.py)（实时）、[`plot.py`](../../plot.py)（曲线）

---

## 1. 为什么 RL 的 bug 特别难发现

**监督学习的 bug 会喊，RL 的 bug 只会沉默。**

图像分类里数据管线错了，准确率卡在 10%，你立刻知道出事了。而 RL 里：

- 损失**照样下降**
- 分数**照样波动**，偶尔冲高，很容易解读成"在学，只是慢"
- **没有任何异常抛出**，每一行代码都"能跑"

旧管线跑了 13 小时，日志里看不出任何问题 —— 因为日志里
只有 `(episode, score, max, avg100)` 四个量。

**结论：诊断能力取决于你记录了什么。** 记录不全，再有经验也看不出来。

## 2. 六个核心指标

`train.csv` 和 `episodes.csv` 里的这几列，是判断健康的主要依据。

### ① `recent100_pipes` —— 主指标

近百局平均过管道数。与奖励尺度无关，**跨版本可比**。

| 现象 | 含义 |
|---|---|
| 长期贴在 0.63（随机基线）| 完全没在学 |
| 缓慢上升 | 正常 |
| 上升后**断崖下跌**且不恢复 | 策略塌缩，见第 4 节 |

**注意这是行为策略的成绩**，带着 ε 的随机动作。ε=0.9 时它当然难看。
真实水平看 `eval_pipes_mean`。

### ② `eval_pipes_mean` —— 真实水平

每 500 局一次的贪婪评测。这才是"网络到底多强"。

**但默认只跑 20 局，噪声大到几乎读不出趋势。** 本项目实测的一段：

```
ep 13500: 70.8    ep 15500: 89.05  ← 尖峰
ep 14000: 54.85   ep 16000: 67.0
ep 14500: 51.95   ep 18000: 83.15  ← 尖峰，±142
ep 15000: 52.95   ep 19000: 38.85  ← 低谷
```

标准差经常**超过均值本身**（38.85 ± 48.3）。一两个超长局就能把 20 局的
均值拉高几十。**这条曲线只能看大方向，不能拿单点下结论。**

真正可信的是 `episodes.csv` 里的 `recent100_pipes`（100 局窗口），
以及训练结束后单独跑一次大样本评测：

```bash
python eval.py runs/<时间戳>/best.pt --episodes 100
```

> ### 陷阱一：`eval_epsilon` 不为 0 会系统性低估
>
> 同一个存档跑 100 局，ε=0 得 **389.6** 根，ε=0.01 只得 **63.1** 根。
> 学好之后一局约 2900 次决策，1% 随机率 = 每局约 29 次随机动作，
> 每次都可能致命。**策略越强，失真越大。**
> 见 [07 · 探索策略](07-exploration.md)。

> ### 陷阱二：只看训练分布会漏掉泛化的进步
>
> 实测一轮训练在 ep 20000 之后，`recent100` 和训练分布上的评测都完全不动，
> 看起来已经收敛。但同一批存档在**未见分布**上继续涨了 34–43%。
>
> 原因是训练分布里含有智能体注定过不去的部分（70–80px 窄缝是物理墙），
> 那部分给均值加了一个恒定天花板，把还在改进的策略压得看起来停滞了。
>
> **判断"还该不该继续练"，要同时看训练分布和至少一个未见分布。**
> 完整数据见 [12 · 怎么判断网络该多大](12-network-sizing.md) 附二。

### ③ `q_mean` 和 `target_q_mean` —— 价值有没有在传播

这是**最有诊断价值**的一对，而旧管线完全没记录。

| 现象 | 含义 |
|---|---|
| 从 ≈0 缓慢上升，两条线贴合 | ✅ 健康 |
| 长期贴在 0 不动 | ❌ 价值没在传播（目标网络不同步？奖励丢了？）|
| 单调爆涨到几百上千 | ❌ 发散（Double DQN 没生效？lr 太大？）|
| 剧烈震荡 | ❌ 目标不稳定 |

本项目实测（15500 局时）：

```
q_mean        : 6.696
target_q_mean : 6.695     ← 两者贴合
```

**有理论对照可用**：低分段 `Q ≈ 0.9 × 已过管道数`，
饱和上限 `γ^12.5/(1−γ^7.2) ≈ 12.6`。
Q 冲到 100 一定是发散了，因为回报根本达不到那个值。

### ④ `loss` —— 反直觉的一个

**loss 低不等于好。**

```
loss : 0.0179     ← 本项目，健康
loss : 0.002      ← 旧管线，而一根管道值 +20
```

第二行是灾难信号：如果一根管道值 +20，TD 误差怎么可能只有 0.002？
**只有一种解释：网络完美拟合了一个长期不动的、错误的目标。**

（旧管线目标网络 13 小时只同步十几次，目标几乎是常数。）

健康的 loss 应该：

- 在合理量级（本项目奖励 ±1，loss 在 0.01–0.05 之间）
- **每次目标网络同步后出现锯齿** —— 目标跳变，loss 应声上升，再被拟合下去

`plot.py` 的第 3 张图把同步时刻画成竖线叠在 loss 上，专门看这个。

看不到锯齿有两种可能：学到头了（在线网络和目标网络已经很接近），
或者同步根本没发生。

### ⑤ `syncs` —— 目标网络同步次数

累计计数。应该稳定增长。

```
grad_step 75000, syncs 75          ← 每 1000 梯度步一次，对上了
```

`syncs` 长期为 0 意味着梯度步压根没跑起来 —— 检查是不是还在 warmup、
缓冲区够不够 `batch_size`。

### ⑥ `grad_norm` —— 裁剪阈值合不合适

记录的是**裁剪前**的梯度范数。

| 现象 | 含义 |
|---|---|
| 稳定在 `grad_clip`（10）以下 | ✅ 裁剪很少生效，阈值合适 |
| 频繁顶到 10 | 梯度偏大，可能 lr 太高或奖励尺度不对 |
| 恒等于 10 | ❌ 每批都被裁，等于偷偷降低了学习率 |

## 3. 实时监控

```bash
python monitor.py                    # 自动盯最新的 runs/ 目录
python monitor.py runs/<时间戳>
python monitor.py --interval 10
python monitor.py --once             # 打印一次（适合脚本）
```

一屏：

```
 阶段  anneal 1 (eps 1.0 -> 0.05)
       [##--------------------------]   8.4%
 近百局均分      0.370 根管道   (随机基线 0.63)  … 仍在随机基线附近
 历史最好均分    0.500          单局最高 4 根
 局数 3500     决策步 41009      epsilon 0.9202
 缓冲区 41009 / 100000 (41%)
────────────────────────────────────────────
 梯度步 5000       目标网络同步 5      loss 0.00562
 Q 均值   -0.070  目标 Q   -0.070  |TD| 0.0599  梯度范数 0.200
 吞吐   306 决策/秒   76 梯度步/秒
────────────────────────────────────────────
 最近贪婪评测 @3000 局：9.60 ± 4.86 根   最高 20   局长 81
```

> ### 读这个面板最容易犯的错
>
> 上面写着"近百局均分 0.370，仍在随机基线附近"，
> 下面写着"贪婪评测 9.60 根"。**相差 26 倍。**
>
> 上面那行是 ε=0.92 时的**行为策略**成绩（92% 的动作是乱按的），
> 下面那行才是**网络的真实水平**。别看错行就以为没在学。

`monitor.py` 只用标准库读 CSV，不 import torch/pygame ——
所以训练在 Docker 里跑、监控在宿主机上跑也没问题。

## 4. 六种典型故障

### (a) 完全不学：`recent100` 和 `eval` 都贴在基线

按可能性排查：

1. **梯度步在跑吗** —— 看 `grad_step` 和 `syncs` 是否增长
2. **奖励进去了吗** —— 看 `episodes.csv` 的 `ep_return`，
   过管道的局应该明显更高
3. **经验对齐吗** —— 跑 `python test/test_env_and_buffer.py`，
   单测 4 和 5 专查这个
4. **done 标记正确吗** —— 单测 3

> 旧管线属于这一类，根因是帧跳过错位同时毁掉了动作标签、
> 75% 的奖励和 75% 的 terminal。

### (b) Q 值爆炸

`q_mean` 单调上涨到几百。检查：

- Double DQN 是不是真的生效（`a_star` 用在线网络选、`q_next` 用目标网络打分）
- `(~d)` 那一项在不在 —— 终止态还自举会无限累积
- 目标网络同步是不是太频繁（退化成没有目标网络）
- lr 是不是太大

### (c) 学一半塌掉

`recent100` 涨到不错然后断崖下跌不恢复。常见原因：

- **缓冲区太小**，好策略的经验被新数据挤掉了，网络灾难性遗忘
- ε 降得太快，探索不足，卡在局部
- 目标网络同步太慢，追不上在线网络

`best.pt` 的存在就是为了兜住这种情况 —— 塌之前的最好模型还在。

### (d) loss 极小但分数不涨

**这是最危险的一种**，因为看起来"很收敛"。

意味着网络完美拟合了一个错误的目标。查：

- 目标网络同步频率（是不是几乎没同步过）
- 奖励尺度（loss 的量级应该和奖励量级相称）
- 数据里到底有没有正奖励样本

### (e) 训练时不错，贪婪评测很差

`plot.py` 第 6 张图专门对比这两条线。

如果贪婪明显低于带 ε 的行为策略，说明**贪婪策略本身有问题**：

- 网络在推理时是随机的（Dropout/BatchNorm 没切 eval 模式）——
  跑一下 `assert_deterministic` 就能确认
- 评测路径里有按训练进度短路的分支（旧管线的经典 bug）
- 确定性策略陷入死循环（这也是评测用 ε=0.01 而非 0 的原因）

### (f) 吞吐掉到 0

`dec_per_s` / `grad_per_s` 归零。查内存 —— 缓冲区太大导致系统开始
swap，是最常见的原因。用 `--buffer` 调小。

## 5. 诊断图

```bash
python plot.py runs/<时间戳>          # 训练进行中也能画
```

六张图，各有分工：

| 图 | 内容 | 主要看 |
|---|---|---|
| 1 | 过管道数 + 随机基线 | 有没有越过 0.63 |
| 2 | **Q 值 + 目标同步竖线** | 价值有没有在传播 |
| 3 | **loss（对数轴）+ 同步竖线** | 有没有锯齿 |
| 4 | ε 曲线 + 每局决策数 | 局长应随水平增长 |
| 5 | TD 误差 + 梯度范数 | 裁剪是否过紧 |
| 6 | 贪婪评测 vs 行为策略 | 两条线应同向 |

**第 2、3 张是关键**，也正是旧管线完全没有的那两张。

## 6. 十个单测

```bash
python test/test_env_and_buffer.py
```

每个测试对应一个**真实存在过的** bug：

| # | 测什么 | 旧实现错在哪 |
|---|---|---|
| 1 | 奖励累加 + 势能望远镜求和 | 塑形项被截断到 ±0.01 |
| 2 | 同帧得分 + 撞死 | 用赋值，`-2` 吃掉 `+20` |
| 3 | terminal 观测是真实崩溃帧 | 先 reset 再绘制 |
| 4 | 帧栈对齐，无跨局拼接 | 无条件 `s_t = s_t1` |
| 5 | 帧跳过的动作/奖励对齐 | `step += 1` 夹在两个 `% k` 之间 |
| 6 | 网络推理确定性 | Dropout(0.3) + 从不 eval() |
| 7 | 跳过渲染不改变物理 | — |
| 8 | 观测路径像素级等价 | — |
| 9 | 难度旋钮生效 | PIPEGAPSIZE 写死 |

> **测试挂了，先想想是不是把某个旧缺陷改回来了，不要直接改断言。**

## 7. 一个务实的排查顺序

怀疑训练有问题时，按这个顺序走，从便宜的开始：

```
1. 跑单测                    30 秒    → 排除结构性 bug
2. 看 monitor.py             10 秒    → grad_step 和 syncs 在涨吗？
3. 看 q_mean                 10 秒    → 在 0 附近不动？还是爆炸？
4. 看 loss 量级              10 秒    → 和奖励量级相称吗？
5. 看 eval vs recent100      看图     → 贪婪明显更差？
6. python train.py --smoke   几分钟   → 缩小配置能跑通吗？
7. shaping_coef = 0 跑一轮   十几分钟 → 塑形在帮忙还是添乱？
```

**不要一上来就调超参数。** 在 RL 里，"调参"往往是在给数据管线的 bug
打掩护 —— 本项目新管线的**第一次**训练就收敛了，
用的是标准的 Double-DQN 超参数，一个都没调。

## 小结

| 指标 | 健康 | 有病 |
|---|---|---|
| `recent100_pipes` | 缓慢上升 | 长期贴 0.63 |
| `eval_pipes_mean` | 趋势向上（噪声大正常） | 不动 / 断崖 |
| `q_mean` | 从 0 缓升，跟着 target | 贴 0 / 爆炸 / 震荡 |
| `target_q_mean` | 与 `q_mean` 贴合 | 长期偏离 |
| `loss` | 量级与奖励相称，有锯齿 | **极小且平坦** |
| `syncs` | 稳定增长 | 长期为 0 |
| `grad_norm` | 低于 `grad_clip` | 恒等于阈值 |
| `dec_per_s` | 稳定 | 掉到 0（内存 swap）|

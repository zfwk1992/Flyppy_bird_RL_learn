# 03 · Dueling 网络架构

Dueling DQN（Wang et al., 2016）只改网络的**最后一段**，不改任何训练算法。
改动很小，但在本项目这种"大部分时候动作无所谓"的任务上收益明显。

---

## 1. 动机：V 和 A 的信息量差别很大

回忆两个价值函数：

- `V(s)`：状态 s 有多好（与动作无关）
- `Q(s,a)`：在 s 做 a 有多好

定义**优势函数**（advantage）：

```
A(s,a) = Q(s,a) − V(s)
```

它衡量"做 a 比该状态的平均水平好多少"。按定义，
`E_{a~π}[A(s,a)] = 0` —— 优势的均值为零。

### 在 Flappy Bird 里的具体含义

考虑两种情形：

**情形 A：小鸟在管道缝隙正中央，水平方向离管道还远。**
这一帧扇不扇翅膀，几乎不影响结果 —— 下一帧再决定完全来得及。
`A(s, 扇) ≈ A(s, 不扇) ≈ 0`。真正重要的是 `V(s)`：
"我现在位置不错，预期还能过很多根管道。"

**情形 B：小鸟正在快速下坠，马上要撞到下管道边缘。**
这一帧**必须**扇翅膀。`A(s, 扇)` 远大于 `A(s, 不扇)`。

**绝大多数帧属于情形 A。** 这正是 Dueling 的用武之地。

---

## 2. 标准 DQN 的浪费

标准 DQN 直接输出两个 `Q(s,a)`。要学好它们，网络必须为**每个动作**
分别学一遍"这个状态有多好"。

而在情形 A 那样的帧里，`Q(s,扇)` 和 `Q(s,不扇)` 几乎相等，
两者都约等于 `V(s)`。网络等于把同一个量（状态价值）学了两遍，
而且**只有被执行过的那个动作会收到梯度**：

```python
q_sa = self.online(s).gather(1, a.unsqueeze(1))    # 只取执行过的动作
```

所以 `Q(s, 没执行的动作)` 在这条样本上完全学不到东西 ——
即使那个动作的价值几乎和执行过的一样。

---

## 3. Dueling 的做法

把网络的最后一段拆成两个头：

```
                        ┌──→ value      → V(s)      标量
共享卷积 → 共享 fc(512) ─┤
                        └──→ advantage  → A(s,a)    每个动作一个
```

然后合成 Q：

```
Q(s,a) = V(s) + A(s,a) − mean_{a'} A(s,a')
```

代码 [`flappy/model.py`](../../flappy/model.py)：

```python
self.fc        = nn.Linear(64 * 6 * 6, 512)
self.value     = nn.Linear(512, 1)          # V(s)
self.advantage = nn.Linear(512, n_actions)  # A(s,a)

def forward(self, x):
    ...
    x = F.relu(self.fc(x.flatten(1)))
    v = self.value(x)                        # (N, 1)
    a = self.advantage(x)                    # (N, 2)
    return v + a - a.mean(dim=1, keepdim=True)
```

### 好处

`value` 头在**每条样本**上都收到梯度，不管当时执行的是哪个动作。
状态价值的学习不再被"只有一个动作有标签"拖累。

在情形 A 占绝大多数的任务里，这等于把大部分样本的学习信号
从"只更新一个动作"变成了"更新整个状态的价值"。

---

## 4. 为什么必须减去均值

这是 Dueling 唯一有技术含量的地方。

### 可识别性问题

如果直接写 `Q(s,a) = V(s) + A(s,a)`，那么给 `V` 加上任意常数 c、
同时给所有 `A` 减去 c，`Q` 完全不变：

```
Q = (V + c) + (A − c) = V + A
```

也就是说，**从 Q 无法反推出唯一的 V 和 A**。网络没有任何约束把
`V` 学成真正的状态价值，两个头可以任意漂移（比如 V 跑到 +1000、
A 跑到 −1000），数值上极不稳定。

### 减均值就固定了这个自由度

```
Q(s,a) = V(s) + [ A(s,a) − mean_{a'} A(s,a') ]
```

方括号里的量，其均值恒为 0。于是：

```
mean_a Q(s,a) = V(s)
```

`V` 被钉死为"Q 在动作上的均值"，多余的自由度消失了。

### 为什么用 mean 而不是 max

论文里也讨论过 `Q = V + (A − max A)`。这样 `V(s) = max_a Q(s,a)`，
在语义上更贴近 `V*` 的定义。

但实践中 **mean 更稳定**：`max` 只把梯度传给一个动作，而且
最优动作切换时会产生跳变；`mean` 让所有动作平滑地参与，优化更好走。
原论文和后续工作基本都用 mean。

---

## 5. 怎么验证它真的在工作

Dueling 不会改变 `Q` 的语义，所以外部指标（过管道数）看不出直接区别。
但可以观察两个头的行为：

```bash
python eval.py runs/<时间戳>/best.pt --episodes 30 --q-stats
```

输出里的 `mean |Q1-Q0|` 就是 `|A(s,扇) − A(s,不扇)|` 的平均
（因为 V 在相减时抵消了）：

```
mean max-Q    : 10.234   (low-score rule: ~0.9 x pipes; ceiling ~12.6)
mean |Q1-Q0|  : 0.412    (action preference strength)
```

解读：

- **`|Q1−Q0|` 平均值不大是正常的** —— 印证了"大部分帧动作无所谓"。
- 但它**不该接近 0**。真接近 0 说明网络分不清两个动作，
  那么 argmax 就是在掷骰子。
- `max-Q` 应该随水平提高而上升，并饱和在 12.6 附近
  （见 [01 · 强化学习基础](01-rl-basics.md) 的推导）。

想更直观地看，跑可视化：

```bash
python play.py runs/<时间戳>/best.pt --scale 2
```

HUD 上有一条 Q 差值条。你会看到**大部分时间它很短**（动作无所谓），
而在小鸟接近管道边缘、需要果断扇翅时**突然拉长** ——
这就是优势函数在起作用。

---

## 6. 常见误解

**"Dueling 是一种新的 RL 算法。"**
不是。它只是网络架构。训练算法完全还是 Double-DQN，
`learn()` 里一个字都不用改。

**"Dueling 一定比标准 DQN 好。"**
不一定。在每个动作都举足轻重的任务里（比如需要精细连续控制的），
优势差异本来就大，Dueling 的收益就小。它的优势恰恰来自
"多数状态下动作无所谓"这个结构性特点 —— Flappy Bird 非常符合。

**"V 头输出的就是状态价值，可以直接拿来用。"**
减均值之后 `V(s) = mean_a Q(s,a)`，这是**动作均值**，
不等于最优策略下的 `V*(s) = max_a Q(s,a)`。两者差一个优势的最大值。

---

## 小结

```
                       ┌──→ Linear(512,1) ──→ V(s)
conv 栈 → Linear(512) ─┤                                  Q = V + A − mean(A)
                       └──→ Linear(512,2) ──→ A(s,a)
```

| 点 | 说明 |
|---|---|
| 解决什么 | 多数状态下动作无所谓，`V` 该被独立、高效地学 |
| 关键细节 | 必须减均值，否则 V/A 分解不唯一，数值发散 |
| 为什么用 mean | 比 max 稳定，梯度分布到所有动作 |
| 改了什么 | 只改网络最后一段，训练算法完全不动 |
| 怎么验证 | `--q-stats` 看 `|Q1−Q0|`，或 `play.py` 看 HUD 的差值条 |

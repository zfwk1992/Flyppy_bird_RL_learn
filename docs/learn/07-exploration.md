# 07 · 探索策略

RL 的根本困境：**要利用已知的好动作（exploitation），
还是尝试没试过的动作看看是不是更好（exploration）？**

只利用 → 卡在第一个还凑合的策略上。
只探索 → 永远学不会用学到的东西。

代码：[`flappy/rollout.py`](../../flappy/rollout.py)、
[`flappy/agent.py`](../../flappy/agent.py)

---

## 1. ε-贪婪

最简单也最常用的方案：以 ε 的概率随机，以 1−ε 的概率贪婪。

```python
# flappy/agent.py
def act_epsilon_greedy(self, stack_uint8, epsilon):
    if random.random() < epsilon:
        return sample_random_action(self.cfg)
    return self.act(stack_uint8)
```

`ε` 从 1.0（纯随机）慢慢退火到 0.01（99% 贪婪）。

---

## 2. 退火曲线

```python
# flappy/rollout.py
def epsilon_at(decision_step, cfg):
    if decision_step < cfg['warmup_decisions']:          # 20,000
        return cfg['eps_start']                          # 1.0
    t = decision_step - cfg['warmup_decisions']
    a1 = cfg['eps_anneal1_decisions']                    # 250,000
    a2 = cfg['eps_anneal2_decisions']                    # 500,000
    if t < a1:
        return cfg['eps_start'] + (cfg['eps_mid'] - cfg['eps_start']) * (t / a1)
    if t < a1 + a2:
        return cfg['eps_mid'] + (cfg['eps_final'] - cfg['eps_mid']) * ((t - a1) / a2)
    return cfg['eps_final']                              # 0.01
```

三段：

```
ε
1.0 ┤━━━━━━━┓
    │       ┃╲
    │       ┃ ╲  第一段：快速降到 0.05
    │       ┃  ╲
0.05┤       ┃   ╲______
    │       ┃          ╲___ 第二段：缓慢降到 0.01
0.01┤       ┃              ╲━━━━━━━━━━━━
    └───────┴───┴──────────┴─────────────→ decision_step
            2万        27万           77万
          warmup    anneal1       anneal2
```

| 阶段 | 决策步 | ε | 在干什么 |
|---|---|---|---|
| warmup | 0 – 20k | 1.0 | 纯随机填缓冲区，**完全不学习** |
| anneal 1 | 20k – 270k | 1.0 → 0.05 | 主要学习阶段 |
| anneal 2 | 270k – 770k | 0.05 → 0.01 | 精调 |
| exploit | 770k+ | 0.01 | 主要利用 |

### 为什么第一段陡、第二段缓

`ε` 从 1.0 到 0.05 是"从瞎走到基本按策略走"，这一段跨度大、
必须走完才能开始积累高质量经验，所以给 25 万步一口气降下去。

`0.05 → 0.01` 是精调：此时策略已经不错，再降 ε 主要是减少
"随机动作把好局面搞砸"的干扰。这一段慢慢来，
让缓冲区里的数据分布平滑过渡。

## 3. 一个计数器原则

`epsilon_at()` **只依赖 `decision_step` 一个参数**。

这看起来是废话，但旧管线正是栽在这里：衰减挂在 `decision_step` 上，
而 ε 的**下限**（0.5 / 0.2 / 0.1 三档）挂在 `episode_count` 上。
两个计数器的关系随策略变好而漂移（局越来越长 → 同样的 episode 数
对应越来越多的 decision），于是 ε 曲线的形状完全不可预测。

旧代码里还有一个占空比 0.08% 的"探索脉冲"，实际上什么也没做。

> **本项目的约定**：所有计数量的单位写进变量名
> （`*_decisions` / `*_grad_steps` / `*_episodes`），
> 跨单位比较一眼可见。见 [docs/ARCHITECTURE.md](../ARCHITECTURE.md) 第 3 节。

## 4. warmup 期不用 if，用 ε=1.0

```python
if decision_step < cfg['warmup_decisions']:
    return cfg['eps_start']        # 1.0
```

warmup 期间"全随机"是通过**让 ε 返回 1.0** 实现的，
而不是在动作选择里写一条 `if step < warmup: return random()`。

区别很重要：

- `epsilon` 这一列**永远等于实际的随机动作比例**，日志可信
- 动作选择路径上**没有任何按训练进度短路的分支**

旧管线在 `select_action()` 里埋了一条：

```python
if self.decision_step < self.training_start:    # 20000
    return random.randrange(self.actions)
```

而 `load_model()` **从不恢复 `decision_step`**。评测脚本新建 agent 时
`decision_step = 0`，于是**每次评测的前 20000 次决策都是纯随机的**，
`--epsilon 0` 也不起作用。113 个存档没有一个有过可信的评测数据。

**教训：不要在动作选择里放训练相关的条件分支。**

## 5. 随机动作为什么是 p_flap = 0.2

这是本项目一个不显眼但影响很大的设计。

```python
def sample_random_action(cfg):
    """随机动作按 p_flap≈0.2 采样，而非均匀的 0.5。"""
    return 1 if random.random() < cfg['eps_random_flap_prob'] else 0
```

### 均匀随机为什么很糟

直觉上"随机"就是两个动作各 50%。但看物理：

```
扇翅：velY = −5（瞬间上升）
重力：velY += 0.5 每帧（最大下落速度 5）
```

一次扇翅后，要 **10 帧**速度才回到 0，约 **19 帧**净位移才归零。
一次决策 = 4 帧，所以一次扇翅的影响跨越约 **5 次决策**。

如果每次决策有 50% 概率扇翅，平均每 2 次决策就扇一次 ——
远快于下落把高度拉回来的速度。**小鸟会被一路顶到天花板上**，
然后贴着顶部飞到撞管道。

### 悬停对应的扇翅率

要让净位移长期为零，扇翅频率应该是"每 5 次决策一次"，即

```
p_flap = 1/5 = 0.2
```

这样随机策略产生的轨迹会在屏幕中部游荡，**覆盖有意义的状态空间**。

### 效果

| p_flap | 随机策略平均过管道数 |
|---|---|
| 0.5 | 接近 0（贴天花板） |
| **0.2** | **0.63** |

0.63 就是 `plot.py` 第 1 张图和 `monitor.py` 面板上的**随机基线**。
任何低于它的策略，说明还不如乱按。

### 这样改合法吗

**合法**，因为 Q-learning 是 **off-policy** 的：
目标里用的是 `max_{a'} Q(s',a')`，与产生数据的行为策略无关。
我们可以自由设计行为策略去收集更有信息量的数据，
学到的 Q 依然收敛到同一个 `Q*`。

> 这是 off-policy 最实用的一个性质。见
> [01 · 强化学习基础](01-rl-basics.md) 第 6 节。

## 6. warmup：20000 次决策不学习

```python
if (decision_step > cfg['warmup_decisions']
        and len(buffer) >= cfg['batch_size']
        and decision_step % cfg['train_every_decisions'] == 0):
    stats = agent.learn(buffer)
```

为什么要等：

1. **缓冲区太小时采样重复度高**。刚开始只有几百条经验，
   一个 batch 128 会反复采到同几条，梯度估计毫无意义。
2. **早期数据相关性极强**，都来自同一局的连续帧。
3. **让 Q 从一个安静的起点开始**。初始 Q≈0，早期几个梯度步
   如果基于极端数据，可能把网络推到一个很差的初始化。

20000 次决策 ≈ 2000 局随机策略的游戏，几秒钟就跑完（GPU 上）。

## 7. 评测时的 ε

训练时的成绩（`recent100_pipes`）是**行为策略**的成绩，
带着 ε 的随机动作。ε=0.9 时它当然很难看 —— 90% 的动作是乱按的。

**真实水平要看贪婪评测**：

```python
eval_epsilon = 0.0         # 训练中的定期评测。必须是 0，见下
```

> ### 这是读监控面板时最容易误判的一点
>
> ```
> 近百局均分      0.370 根管道   (随机基线 0.63)  … 仍在随机基线附近
> 最近贪婪评测 @3000 局：9.60 ± 4.86 根   最高 20
> ```
>
> 上面那行是 ε=0.95 时的行为策略成绩，下面那行才是网络的真实水平。
> **两者相差 26 倍。** 别看错行。

### 评测的 ε 必须是 0 —— 一个真实踩过的坑

本项目最初把 `eval_epsilon` 设成 0.01，理由是"防止确定性策略陷入死循环"。
这个理由本身没错，但**代价被严重低估了**。

同一个存档、同样跑 100 局，只改 ε：

| ε | 平均过管道 | 中位数 | 跑满 4000 决策上限仍活着 |
|---|---|---|---|
| **0.00** | **389.6 ± 177.0** | **521** | **46 / 100** |
| 0.01 | 63.1 ± 66.3 | 41 | 0 / 100 |

**6.2 倍差距。**

原因是**存活概率随局长指数衰减**。策略学好之后，一局有约 2900 次决策，
1% 的随机率意味着每局约 **29 次**随机动作。在 100px 的缝隙里，
一次错误时机的扇翅基本就是死。

```
存活到第 n 次决策的概率 ≈ (1 − ε·p_fatal)^n
```

`n` 越大，惩罚越重。**策略越强，ε 造成的失真就越大** ——
这是最坏的一种偏差：它专门惩罚好模型。

> 训练过程中的定期评测因此一直在系统性低估策略，
> 报出来的是 38–89 根，而真实水平是 389.6 根。

**死循环怎么办？** 用 `max_episode_decisions` 的长度上限兜底 ——
它本来就存在（防止无限长的回合卡住日志和评测）。
用上限来防循环，不要用注入随机动作来防循环。

## 8. 更好的探索方法

ε-贪璪很简单，但它的探索是**无方向**的 —— 随机动作不区分
"这个状态我很熟"和"这个状态我从没见过"。

更高级的方案：

- **Noisy Nets**：把噪声加进网络权重，噪声幅度可学习。
  探索量自适应，且状态相关。
- **内在好奇心（ICM / RND）**：给"预测不准"的状态额外奖励，
  主动去没去过的地方。
- **Bootstrapped DQN**：多个 Q 头，每局随机挑一个，
  用头之间的分歧表示不确定性。

本项目没用这些，因为 **Flappy Bird 的探索问题不难**：
状态空间小，随机策略也能偶尔过管道（0.63 根），
ε-贪婪配上正确的 `p_flap` 已经够了。

**先把简单的做对，再考虑复杂的。**

---

## 小结

| 点 | 值 | 理由 |
|---|---|---|
| 策略 | ε-贪婪 | 简单、够用 |
| ε 曲线 | 1.0 → 0.05 → 0.01，两段线性 | 先快速脱离随机，再精调 |
| 计数器 | 只用 `decision_step` | 混用计数器会让曲线不可预测 |
| warmup | 靠 ε=1.0 实现，不写 if | 日志里 ε 永远等于真实随机率 |
| 随机扇翅率 | **0.2** 而非 0.5 | 0.5 会把鸟顶死在天花板 |
| 随机基线 | 0.63 根管道 | 判断"有没有在学"的标尺 |
| 评测 ε | **必须 0.0** | 0.01 会让成绩差 6.2 倍，且专门惩罚好模型 |

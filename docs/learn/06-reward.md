# 06 · 奖励设计与势能塑形

奖励函数定义了"什么叫做得好"。**它写错了，其他一切都白搭** ——
网络会忠实地学会你实际奖励的东西，而不是你想要的东西。

代码：[`game/flappy_env.py`](../../game/flappy_env.py)、
[`flappy/rollout.py: skip_step()`](../../flappy/rollout.py)

---

## 1. 本项目的奖励

| 事件 | 奖励 | 配置项 |
|------|------|--------|
| 过一根管道 | `+1.0` | `pipe_reward` |
| 撞死（管道或地面） | `−1.0` | `death_reward` |
| 存活每帧 | `0.0` | `alive_reward` |
| 势能塑形 | `0.05 × (γΦ(s′) − Φ(s))` | `shaping_coef` |

三个设计决定，每个都有代价换来的理由。

---

## 2. 为什么归一化到 ±1

旧管线用 `+20 / −2`。看起来只是尺度问题，实际影响三个地方：

### (a) Huber 损失的拐点固定在 δ=1

```python
loss = F.smooth_l1_loss(q_sa, y)
```

Huber 在 `|δ| ≤ 1` 时是平方（梯度 ∝ δ），`|δ| > 1` 时是线性（梯度恒为 ±1）。

奖励是 +20 时，含管道样本的 TD 误差动辄十几二十，**几乎全部落在线性区**。
于是"TD 误差 = 2"和"TD 误差 = 20"产生**完全一样的梯度** ——
误差大小的信息被丢掉了，学习效率骤降。

归一化到 ±1 后，绝大多数 TD 误差落在平方区，梯度正比于误差。

### (b) 梯度裁剪阈值

`grad_clip=10` 是按"奖励量级约为 1"设的。奖励放大 20 倍，
梯度也大致放大 20 倍，裁剪就会对**每一批**生效 ——
等于偷偷把学习率变成了自适应的，而且是错误的那种。

### (c) Q 值可读

归一化后 `Q_mean ≈ 0.9 × 已过管道数`（低分段），
`Q ∈ [−1, 12.6]`。看一眼 `train.csv` 的 `q_mean` 就知道网络认为自己多强。

Q 值上限的推导：一个永不死亡的策略，

```
Q_max = γ^12.5 / (1 − γ^7.2) ≈ 12.6
```

12.5 是管道从生成到得分的决策数，7.2 是相邻管道的决策间隔。
`eval.py --q-stats` 会打印这个对照。

> **经验法则**：把奖励设计成量级约为 1。这不是美学，
> 它决定了损失函数、梯度裁剪、优化器超参是否工作在设计区间内。

## 3. 为什么存活奖励是 0

直觉上"活着就该给点奖励"，但这会引出**退化策略**。

假设 `alive_reward = 0.01`，过管道 `+1`。一个学会在管道前**悬停**、
永不前进的智能体（Flappy Bird 里管道会自己撞过来，所以严格说做不到，
但在缝隙里磨时间是可能的），每帧稳拿 0.01，风险为零。

而尝试通过管道有撞死的风险（`−1`）。折算下来，**苟活可能比冒险划算**。

> 旧管线正是这样：它的存活奖励带衰减，管道 `+20`，但由于帧跳过丢掉了
> 75% 的管道奖励，实际收到的信号里存活项的占比被放大了。
> 结果就是学出一个"尽量别死"而不是"尽量过管道"的策略。

设成 0 之后，**唯一的正奖励来源就是过管道**。目标毫无歧义。

那"不要死"怎么表达？靠 `death_reward = −1` 和折扣：
死了就拿不到后面的 `+1` 了，这本身就是最强的存活激励。

## 4. 势能塑形

### 问题：奖励太稀疏

只有过管道才有 `+1`。随机策略下，小鸟平均活 10 次决策就死，
可能几百局才碰巧过一根管道。学习信号极其稀疏，冷启动非常慢。

### 做法：给一个"引导"信号

定义势能函数 `Φ(s)`：小鸟中心到下一根管道缝隙中心的竖直距离（取负）。

```python
# game/flappy_env.py
def current_potential(self):
    nxt = None
    for uPipe in self.upperPipes:
        if uPipe['x'] + PIPE_WIDTH > self.playerx:    # 用尾缘判定
            nxt = uPipe
            break
    if nxt is None:
        return 0.0
    gap_center = nxt['y'] + PIPE_HEIGHT + self.pipe_gap / 2.0
    d = abs(self.playery + PLAYER_HEIGHT / 2.0 - gap_center) / SCREENHEIGHT
    return -float(d)
```

`Φ ∈ [−1, 0]`，无量纲（除以 `SCREENHEIGHT` 而不是硬编码的常数）。
越靠近缝隙中心，`Φ` 越接近 0（越好）。

然后把**势能差分**加进奖励：

```python
r_shaped = r + 0.05 × (γ·Φ(s′) − Φ(s))
```

朝缝隙中心移动 → 差分为正 → 额外奖励。这给了智能体一个**密集**的信号。

---

## 5. 为什么必须是「差分」形式

这是本节的核心。**随便加一个"靠近中心就给奖励"的项是危险的**，
它会改变最优策略 —— 智能体可能学会一直贴着缝隙中心飞而不往前推进。

### Ng-Harada-Russell 定理（1999）

如果塑形项具有**势能差分**形式

```
F(s, a, s′) = γ·Φ(s′) − Φ(s)
```

那么在 `R + F` 下的最优策略与在 `R` 下的**完全相同**。

### 直觉：望远镜求和

把塑形项沿一整条轨迹累加：

```
Σ_t γ^t · [γ·Φ(s_{t+1}) − Φ(s_t)]
  = [γΦ(s₁) − Φ(s₀)] + γ[γΦ(s₂) − Φ(s₁)] + γ²[γΦ(s₃) − Φ(s₂)] + ...
  = −Φ(s₀) + γΦ(s₁) − γΦ(s₁) + γ²Φ(s₂) − γ²Φ(s₂) + ...
  = −Φ(s₀) + lim γ^T Φ(s_T)
```

中间项**全部消掉**（望远镜求和）。只剩下一个与策略无关的常数 `−Φ(s₀)`，
以及终止时趋于 0 的尾项。

**给所有策略的回报加同一个常数，不改变哪个策略最优。**
所以塑形只加速学习，不扭曲目标。

单测 1 (`test_reward_accumulation_and_telescoping`) 直接验证这个求和，
实测误差 **3e-17**（浮点精度极限）。

## 6. 两个容易毁掉这个保证的错误

### 错误一：截断

旧代码：

```python
potential_reward = gamma * current_potential - self.previous_potential
return max(-0.01, min(0.01, potential_reward))     # ← 截断
```

一截断，`F` 就**不再等于** `γΦ(s′) − Φ(s)`，望远镜求和不成立，
策略不变性**失效**。塑形项退化成一个会扭曲最优策略的普通奖励。

这条 bug 让"势能塑形"从一个安全的加速手段变成了一个隐蔽的目标污染源。

### 错误二：在帧级施加，而不是决策级

本项目一次决策 = 4 帧。如果按帧施加塑形：

```
Σ_{i=0..3} [γ_frame·Φ(s_{t+i+1}) − Φ(s_{t+i})]
```

这个和**不等于** `γ_dec·Φ(s_{t+4}) − Φ(s_t)`，因为帧级折扣 `γ_frame`
和决策级折扣 `γ_dec` 不是一回事。策略不变性同样不精确成立。

所以本项目的做法是：环境**只暴露 Φ**，差分由调用方在**决策级**计算：

```python
# flappy/rollout.py: skip_step()
phi_next = 0.0 if done else info['potential']
r_dec = r_raw + cfg['shaping_coef'] * (cfg['gamma'] * phi_next - phi_prev)
```

而旧代码在环境内部、**动作施加之前**算差分，得到的是
`γΦ(s_t) − Φ(s_{t-1})` —— 与当前动作完全无关，纯噪声。

### 终止态的 Φ 必须是 0

```python
phi_next = 0.0 if done else info['potential']
```

定理要求 `Φ(terminal) = 0`，否则尾项 `γ^T Φ(s_T)` 不消失，
不同策略的常数就不同了。

---

## 7. `shaping_coef = 0.05` 怎么来的

理论上塑形不改变最优策略，系数取多少都行。但实践中它影响**学习速度**：

- 太大 → 塑形项淹没真实奖励，早期学习被引导信号主导，
  可能在真实奖励出现前就收敛到"贴着中心飞"的局部行为
- 太小 → 起不到加速作用

`Φ ∈ [−1, 0]`，单次决策的差分典型量级约 0.1，乘 0.05 后约 0.005 ——
比过管道的 `+1` 小两个数量级。**塑形只是轻轻推一把，不抢主导权。**

单测 1b 验证一整局的塑形项总和绝对值 `< 0.1`，
远小于单根管道的 `+1`。

---

## 8. 一个诊断技巧

如果怀疑塑形有问题，把 `shaping_coef` 设成 0 跑一轮。

- **依然能学会，只是慢** → 塑形是健康的，它只在加速
- **设成 0 反而学得更好** → 塑形在扭曲目标，去查它是不是被截断了、
  是不是在错误的时间点算的

这个对照实验很便宜，值得做。

## 小结

| 决定 | 值 | 理由 |
|---|---|---|
| 奖励尺度 | ±1 | Huber 拐点、梯度裁剪、Q 可读性 |
| 存活奖励 | 0 | 任何正的存活项都诱导"磨时间" |
| 过管道 | +1 | 唯一的正奖励来源，目标无歧义 |
| 撞死 | −1 | 配合折扣，隐含地表达"别死" |
| 塑形形式 | `γΦ(s′) − Φ(s)` | Ng 定理保证不改变最优策略 |
| 塑形系数 | 0.05 | 比真实奖励小两个数量级 |
| 施加位置 | **决策级**，不截断 | 否则望远镜求和不成立 |
| 终止态 Φ | 强制 0 | 否则尾项不消失 |
| 奖励累加 | `+=` 不用 `=` | 同帧可能既得分又撞死 |

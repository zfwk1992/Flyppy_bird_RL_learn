# 教学文档

这个仓库的目的是**学 RL 和神经网络**，不是刷分。所以每一篇文档都尽量做到：
讲清楚**为什么**这么做，并且指向仓库里**真实运行的那几行代码**。

代码里所有的设计选择都是有代价地换来的 —— 这套管线的前身跑了 4 轮、
10 万局、13 小时，成绩停在 1.3 根管道；重写之后 **100 分钟训练，
100 局纯贪婪评测平均 389.6 根**（中位数 521，46% 的局跑满长度上限仍活着）。
中间的差距不在超参数，而在十来个结构性错误。所以第 00 篇不是理论，是验尸报告。

## 建议的学法

1. **先读 00**。它是本仓库最有价值的一篇 —— 你会看到"能跑"和"正确"
   之间隔着多少东西，以及为什么 RL 的 bug 特别难发现（不报错，只是不学）。
2. **01-03 建立概念**，读的时候对着 `flappy/` 里的代码看。
3. **04-07 是本项目的具体实现**，每一节都能在代码里找到对应的行。
4. **08-09 把它们串起来**：训练时数据怎么流，推理时又怎么流。
5. **10 教你自己判断**训练是不是健康的 —— 这是 RL 里最缺的技能。
6. **11 是第二篇"验尸报告"**：模型明明很强，却只是背下了一个窄分布。
   它演示了怎么把"我怀疑它在作弊"变成一个可复现的数字。

## 动手

```bash
python test/test_env_and_buffer.py    # 10 个单测，每个对应一个真实 bug
python train.py --smoke --allow-cpu   # 几分钟看完整管线
python monitor.py                     # 另开终端实时看
python play.py runs/<时间戳>/best.pt   # 看它实际飞
```

改任何东西之后都跑一遍单测。测试挂了先想想是不是把某个旧缺陷改回来了。

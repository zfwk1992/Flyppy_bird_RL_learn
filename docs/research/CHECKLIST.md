### 跑什么

```bash
python train.py --run-dir runs/gap80_s0 --seed 0 \
       --buffer 60000 --max-hours 4 --gap-range 80 165
```

seed 0 是**故意**和 `base_s0` 一样的 —— 配对比较，把"换了 seed"这个
混淆因素去掉。跑完确认 `runs/gap80_s0/config.json` 里
`pipe_gap_range == [80.0, 165.0]`（笔记本上那两次已经确认过参数生效）。

### 验的是什么

**假设**：训练时把缝隙下界压到 80（比现在的 85 更难），推理仍在 demo 部署的
100–165 上，成绩会更好 —— "练重器械"。

**反对意见（有数据，但不完全适用）**：`EXPERIMENTS.md` 的死亡归因显示
70–80px 占 10.5% 的管道却贡献 53.5% 的死亡，是物理墙（70px 缝隙扣掉鸟高
剩 46px，而最小悬停振幅要 22.5px）；当年下界 70 → 85 之后同等训练量下
成绩高 1.7–3.3 倍。

**但那份数据没有单独测过 80**，它对比的是 70–165 vs 85–165，而 80 正好卡在
墙边而不是墙心。所以这条值得实跑，不该靠推断否掉。

### 怎么判（**先定死，别事后挑数字**）

评测一律在 **demo 实际部署的 100–165** 上做，400 局固定集，
和 `runs/base_s0/final.pt` 配对：

```bash
python eval.py runs/gap80_s0/final.pt   --episodes 400 --q-stats --gap-range 100 165
python eval.py runs/base_s0/final.pt    --episodes 400 --q-stats --gap-range 100 165
```

- 主指标 **hazard = 死亡数 / 总通过管道数**，截断局按右删失只进分母
- 相对标准误 = 1/√死亡数
- **差距小于 2 个合并标准误一律写"没有区别"**

### ✅ 对照组已经测出来了（2026-09-07 15:4x，笔记本），不用再跑

`python eval.py runs/base_s0/final.pt --episodes 400 --q-stats --gap-range 100 165`

| | 训练分布 85–165 | **部署分布 100–165** |
|---|---:|---:|
| 平均过管 | 96.91 | **150.95** |
| 中位数 | 74.5 | **151.0** |
| 撞评测上限 | 36/400 | **120/400** |
| 删失校正均值 | 106.49 | **215.64** |
| **hazard** | 0.939% ± 0.049% | **0.464% ± 0.028%** |

**换到部署分布上 hazard 直接减半**（−50.6%，8.4 个标准误）。

**这个数改变了目标线的含义**：云端一直在算"0.939% 减半 = 0.47% 可能不可达
（oracle N=120 才 0.706%）"。但在 demo 真正部署的难度上，当前模型**已经是
0.464%** —— 那条被当作可能不可达的线，换个分布就已经越过去了。
此前所有 Layer-0 诊断都是在 85–165 上做的，而 demo 从来不跑那个分布。

### ⚠️ 尺子不够长，评测要加 --max-decisions

对照组已经有 **120/400 (30%)** 的局撞上 2000 决策的上限。hazard 虽然按右删失
只把截断局记进分母、方向上是保守的，但 30% 的截断率意味着分辨力已经在下降。
新模型如果更强，撞顶的比例只会更高，400 局可能量不出差别。

**两边都要用同一个更大的上限重测**，否则不可比：

```bash
python eval.py runs/base_s0/final.pt  --episodes 400 --q-stats --gap-range 100 165 --max-decisions 6000
python eval.py runs/gap80_s0/final.pt --episodes 400 --q-stats --gap-range 100 165 --max-decisions 6000
```

### 判据（用部署分布上的对照组，不是 85–165 那个）

**新模型要显著低于 0.464% ± 0.028% 才算赢。** 合并标准误约 0.04%，
所以**至少要低到 0.38% 以下**才算"有区别"。

注意这让"训练加难度"这个假设更难赢了 —— 它要打败的不是 0.939%，是 0.464%。

三种结果都要如实写进 `EXPERIMENTS.md`：

| 结果 | 含义 |
|---|---|
| 新模型明显更好 | "训练加难度"成立，反对意见被证伪 |
| 没有区别 | 80 这个幅度不够，或收益被物理墙的噪声抵消 |
| 明显更差 | 支持原判断，80 确实进墙了 |

云端第四轮检索找到两篇之前三轮没搜到的论文，和本项目"动作差距塌缩 → argmax

1. **CHAIN**（NeurIPS 2024）把这个现象叫"greedy action deviation"，

   continual RL + policy-gradient，不是本项目这种单任务 DQN。

**结论：两篇都不能替代本机用 diag.csv 做的直接验证**，因为没有一篇论文在
"单任务/DQN/小尺度/稀疏奖励"这个和本项目完全一致的组合上验证过。它们的
价值是：①确认 `argmax_flip` 这个诊断量本身是有 peer-review 工作背书的
